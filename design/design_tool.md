# Kyanos ツールエコシステム設計仕様書 (Tooling & Ecosystem Design)

本ドキュメントでは、Kyanos 言語の公式ツールチェイン（コンパイラ、REPL、LSP、ビルドシステム、AI連携）のアーキテクチャおよびロードマップを定義する。

---

## 1. LLVM基盤のコンパイラ & セルフホスティング計画

### 1.1 アーキテクチャ (Compiler as a Library)
コンパイラはモノリシックな構成を避け、フロントエンド・中間表現・コード生成の責務を独立したモジュール（クレート/ライブラリ）に分割して設計する。これにより、コンパイラ本体だけでなく REPL、LSP、MCP からも各機能をライブラリとして共有する。

```
[ソースコード]
      ↓
[kyanos-lexer]   : 字句解析 (文字列 -> トークン列)
      ↓
[kyanos-parser]  : 構文解析 (手書き再帰下降 + Pratt Parser -> AST)
      ↓
[kyanos-sema]    : 意味解析 & 型推論 (AST -> 型チェック済みAST & シンボル表)
      ↓
[kyanos-codegen] : 最適化 & コード生成 (ORCメモリ管理挿入 -> LLVM IR -> ネイティブバイナリ)
```

### 1.2 ブートストラッピング方針 (Rustによる初期実装)
* **実装言語**: 初期コンパイラ（Stage 0）は **Rust** を採用する。
  * `inkwell` や `llvm-sys` などの成熟した LLVM バインディングエコシステムを活用し、高速かつ堅牢な単一バイナリとして提供する。
* **Kyanosへの移植性を見据えた構造化**:
  * **手書きパーサーの採用**: 外部のパーサージェネレータやRust独自のマクロ機能に依存せず、手書きの再帰下降パーサーおよび Pratt Parser で実装する。これにより、コード構造をKyanosの構文とほぼ1対1に対応させ、移植コストを最小化する。
  * **データ構造の対応**: ASTのノード構造をKyanos側の型定義（判別共用体・クラス）と素直に対応できる形式で定義する。
  * **段階的セルフホスティング**: モジュールごとに独立しているため、`lexer` $\to$ `parser` $\to$ `sema` $\to$ `codegen` と段階的にKyanos製モジュールへと置き換えることが可能。

### 1.3 セルフホスティングのロードマップ
1. **Phase 1: ブートストラップコンパイラ完成 (Rust製 Stage 0)**
   * 基本構文、型システム、ORCメモリ管理、および **C-FFI（外部関数インターフェース）** を実装。
   * **重要マイルストーン**: Phase 2 に進むための必須前提条件として、Kyanos の C-FFI を通じて LLVM C-API (`llvm-c`) を直接呼び出せるバインディング環境を構築する。
2. **Phase 2: Kyanos によるセルフホストコンパイラ実装 (Stage 1)**
   * Kyanos 自身を用いてコンパイラフロントエンドおよびコード生成系を記述。
   * Rust製コンパイラ（Stage 0）を用いて Kyanos製コンパイラソースをコンパイルし、最初のセルフホストバイナリ（Stage 1）を生成する。
3. **Phase 3: 完全セルフホスティングの検証 (Stage 2)**
   * Stage 1 を用いて自らのソースコードを再コンパイルし、Stage 2 バイナリを生成。
   * Stage 1 と Stage 2 の出力結果が完全一致（再現可能ビルド）することを確認し、ブートストラップを完了する。

## 2. LLVM JIT を活用した REPL & スクリプト実行

### 2.1 LLVM ORC JIT の採用
LLVM の最新 JIT エンジンである **LLVM ORC (On-Request Compilation) JIT** をバックエンドに採用する。入力されたコードをインメモリでオンデマンドにネイティブコードへ変換・実行する。

### 2.2 提供機能
* **対話型シェル (`kyanos repl`)**:
  * 式の即時評価（TypeScriptのNode REPLやPythonのような軽快な操作感）。
  * セッション内でのスコープ・状態保持（変数宣言、関数定義、型定義の動的追加）。
* **高速スクリプト実行 (`kyanos run <file.ky>`)**:
  * ディスク上に実行可能ファイルを残さず、メモリ上で即座にJIT実行する。
  * 設定スクリプトやちょっとしたCLIツールの実行をスクリプト言語の手軽さで行える。

## 3. LSP (Language Server Protocol) サーバー

### 3.1 耐障害性パーサー (Fault-tolerant / Resilient Parser)
エディタ上での入力中はコードが文法的に未完成（エラー状態）であることが大半である。
LSPで使用する構文解析器は、エラー発生時にパニック・停止せず、同期トークン（セミコロンや波括弧など）までスキップする等のエラーリカバリーを行い、可能な限り部分的なASTを構築して補完や型情報を提供する設計とする。

### 3.2 コンパイラフロントエンドの共通化 (Compiler as a Library)
コンパイラ本体の `kyanos-parser` および `kyanos-sema`（型チェック・シンボル解決）をそのままライブラリとして共有する。これにより、コンパイル時の診断結果とエディタ上の表示に齟齬が生じないようにする。

### 3.3 コア機能 (初期MVP)
* **リアルタイム診断 (Diagnostics)**: 入力中に構文エラーや型エラーを即座に赤波線で通知。
* **コード補完 (Completion)**: メソッド名、プロパティ名、キーワード、スコープ内の変数、型シグネチャの補完。
* **定義ジャンプ (Go to Definition)**: `F12` によるシンボルの定義元・型定義元へのジャンプ。
* **ホバー情報 (Hover)**: シンボルにカーソルを合わせた際の型シグネチャおよびドキュメントコメントのポップアップ表示。
* **シンボルのリネーム (Rename)**: プロジェクト全体での安全な一括シンボル名変更。
* **セマンティックハイライト (Semantic Tokens)**: 正規表現ベースの字句解析を超えて、型情報に基づいた正確なコード色分けを提供。

### 3.4 将来の拡張構想 (Phase 2+)
開発の進展に合わせて以下の高度なIDE支援機能を段階的に追加する：
* **インレイヒント (Inlay Hints)**: 型推論された変数型や、関数呼び出し時の引数名ラベルをコード内にインライン表示。
* **コードアクション (Code Actions)**: 未インポートモジュールの自動 `import` 追加、簡単な型不一致のクイックフィックス（Quick Fix）、不要なインポートの整理など。

### 3.5 エディタ連携 (クライアント)
* **サブコマンド**: LSP サーバー本体は単一CLIバイナリ内のサブコマンド `kyanos lsp`（標準入出力 STDIO 経由で通信）として提供する。
* **VS Code 拡張機能**: `kyanos lsp` と通信する公式の軽量クライアント拡張機能（`vscode-kyanos`）を提供する。

## 4. 標準ビルドシステム & パッケージ管理

### 4.1 統合 CLI (`kyanos`)
外部ツールを複数導入することなく、開発に必要な全コマンドを単一バイナリ `kyanos` に集約する。
* `kyanos init [project-name]`: 新規プロジェクト雛形（`kyanos.json`, `src/main.ky`）の生成。
* `kyanos build`: プロジェクトのコンパイル（`--release` で LLVM の `O3` 最適化 / LTO 有効化）。
* `kyanos check`: コード生成をスキップし、構文解析・型チェックのみを超高速に行う。
* `kyanos run [file]`: JITまたはビルド＆即時実行。
* `kyanos test`: 組込みテストランナー（ユニットテスト・統合テストを実行）。
* `kyanos fmt`: 公式コードフォーマッタ。標準スタイルを既定としつつ、JSON設定によるカスタマイズ（インデント幅、クォート種別、末尾カンマ等）に対応。

### 4.2 プロジェクト設定ファイル (`kyanos.json`)
Web / TypeScript エコシステムとの親和性が高い **JSON 形式 (`kyanos.json`)** を採用する。
プロジェクトのメタデータ、エントリポイント、依存関係、Cライブラリのリンク指定、およびフォーマッタ設定などを宣言的に管理する。

```json
{
  "name": "my_app",
  "version": "0.1.0",
  "entry": "src/main.ky",
  "dependencies": {
    "github.com/kyanos-lang/std-http": "v0.1.0"
  },
  "native": {
    "links": ["sqlite3"]
  },
  "fmt": {
    "indent": 2,
    "useTabs": false,
    "semi": true,
    "singleQuote": false,
    "trailingComma": "all",
    "lineWidth": 100
  }
}
```
*(※フォーマット設定は `kyanos.json` 内の `"fmt"` セクション、または単独の `.kyanosfmt.json` から読み込み可能とする)*

### 4.3 パッケージ管理方針 (Gitリポジトリ直接取得)
* **専用中央レジストリは設けない (初期フェーズ)**:
  * crates.io や npm のような専用の巨大中央パッケージリポジトリは初期段階では構築・運用せず、将来的な検討課題とする。
* **GitHub 等からの直接ダウンロード方式**:
  * Go言語（`go get`）や Zig のパッケージマネージャと同様に、GitHub 等のリポジトリ URL およびバージョン（Git タグ、コミットハッシュ）を指定して直接ダウンロード・依存解決を行う。
  * ダウンロードしたパッケージはグローバル/ローカルキャッシュ（例: `~/.kyanos/cache/`）に保存され、ビルド時に参照される。
* **ES Modules との親和性**:
  * プロジェクト内からは `kyanos.json` で定義されたエイリアス、またはリポジトリ識別子を通じて標準的な `import` 構文で利用可能とする。

## 5. MCP (Model Context Protocol) サーバーと AI 連携

### 5.1 概要 & 目的
新しい言語エコシステムにおいて、開発者のみならず AI エージェント（Pair Programmer）が自律的かつ正確に Kyanos コードを読み・書き・検証できるインターフェースを公式提供する。
当面の主要テスト・検証ターゲット環境として **Antigravity** を想定し、開発初期から AI 親和性の高い言語基盤を構築する。

### 5.2 起動方法 (`kyanos mcp`)
* 単一CLIバイナリのサブコマンド `kyanos mcp` により、標準入出力（STDIO）経由で MCP サーバーを起動。
* Antigravity などの MCP クライアント設定にコマンドを登録するだけで即座に連携可能。

### 5.3 提供する主な MCP ツール (Tools)
* **`kyanos_check` (構文・型診断)**:
  * ソースコード文字列またはプロジェクト内ファイルを渡し、構文・型エラーや警告を構造化データ（行・列・エラーメッセージ・修正ヒント）として即時返却。
  * AI エージェントがコード生成・編集直後に自律的なセルフチェック（自己検証ループ）を行うために使用。
* **`kyanos_inspect_symbol` (シンボル・型情報取得)**:
  * プロジェクト内のクラス、メソッド、インターフェース、型の完全なシグネチャやドキュメントコメントを抽出して返却。
* **`kyanos_eval` (JIT 即時評価)**:
  * LLVM ORC JIT エンジンを活用し、コードスニペットをインメモリで安全に即時実行・評価。動作確認やユニットテストの試行をAI主導で行える。
* **`kyanos_doc` (言語仕様・標準ライブラリ検索)**:
  * Kyanos の文法規則（EBNF）や標準ライブラリの API 仕様を検索・取得。AI が最新の言語仕様を正確に参照できるようにする。

### 5.4 提供する MCP リソース (Resources)
* `kyanos://spec/grammar`: 最新の EBNF 文法定義データ。
* `kyanos://ast/<file_path>`: 指定されたソースファイルの抽象構文木（AST）JSON 表現。
